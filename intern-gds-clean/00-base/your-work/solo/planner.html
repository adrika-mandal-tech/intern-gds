Goals

Measurement Rigour

Profile 7 graphs, run algorithms with proper timing, attach provenance. Every number is traceable to a CSV row, every CSV row to a stage, every stage to a command.

Claims Verification

Trace 12 claims to primary sources, grade evidence as production / research / product / marketing, and fill claims.jsonl with verdicts.

Ontology & Interop

Model the domain in RDF/OWL, validate with SHACL, export linked data via gds-owl, and query with SPARQL for cross-lab interoperability.

The Seven Graphs

All graphs are real-world, offline, and require no internet after initial download. Each carries a provenance sidecar recording source URL, SHA-256 checksum, retrieval date, and preprocessing notes.

Weight semantics: In openflights and crime, edges carry distances or co-occurrence counts. These are costs, not strengths: higher weight means harder to traverse. This distinction governs interpretation throughout P3 and P4.
Source citations: Les Misérables — Knuth (1993). UnicodeLang — ISO 639-3 + Unicode CLDR. Crime — San Francisco Police Department open data. email-Eu-core — Boguná et al. (2009). openflights — OpenFlights.org (CC-BY-SA 4.0). facebook_combined — Leskovec & McAuley (2012). ca-GrQc — Newman (2001).

P2 — Centrality & Communities (Parallel Tracks)

Track A: Centrality Track B: Communities Claims: C02, C06, C12 (A); Prep P3B (B) Duration: 2A ~90 s, 2B ~3 min

Goal: Track A measures four centrality measures on 5 graphs, tests pairwise Spearman rank correlation and top-10 overlap, and identifies ranking disagreements. Track B runs Louvain 200 times per graph with 200 seeds to quantify partition stability.

Scope

In Scope (2A) In Scope (2B) Out of Scope (Both)
  • 5 graphs (lesmis, crime, email-Eu-core, openflights, facebook_combined)
  • Degree, closeness, betweenness, PageRank
  • Pairwise Spearman correlation matrices
  • Top-10 overlap (Jaccard) per pair
  • Disagreement analysis with named nodes
  • 5 graphs (same subset)
  • Louvain with 200 random seeds per graph
  • Hash, modularity, ARI recorded per run
  • Spread analysis (std of modularity)
  • Prep: seed range and resolution parameter sweep notes
  • Eigenvector centrality (Tier 3)
  • Weighted vs unweighted on openflights (Tier 3)
  • Leiden (deferred to P3B)
  • CPM (deferred to P3B)

Tier Table

Tier Track A Deliverables Track B Deliverables

Tier 3 Add eigenvector centrality; weighted vs unweighted on openflights Compare with Leiden; test CPM partition

Decision Rules

Condition Action
Louvain gives identical partitions across all 200 seeds Check seed range — likely deterministic without resolution parameter sweep
Spearman high but top-10 overlap low Report both. Explain the trap: rank correlation measures order, not identity of top-k.
One graph crashes in either track Continue with remaining 4. Note in questions.md.

SHACL Validation

The biolink_model.shacl.ttl file contains ~60,074 lines of SHACL shapes. These validate that Knowledge Graph eXchange (KGX) format data conforms to the Biolink Model constraints. Every node and edge in a Biolink-compliant KG must pass these shapes.

LinkML

The biolink_model.yaml is the canonical LinkML schema. LinkML is a YAML-based modelling language that can generate both OWL (TBox) and SHACL (ABox constraints) from a single source of truth. This eliminates the schema-divergence problem that plagues multi-format ontologies.

  • skos:definition — human-readable definition
  • rdfs:subClassOf — class hierarchy with restrictions

Six Families of Graph Algorithms

The algorithms used in this pack fall into six families. Understanding the family helps interpret results and avoid category errors.

Family Algorithms Used Output Key Interpretation Note
Centrality PageRank, Degree, Closeness, Betweenness Score per node Higher score = more central. But "central" depends on definition.
Community Detection Louvain, Leiden Partition (community ID per node) No ground truth in most cases. Modularity is a heuristic.
Similarity & Prediction Jaccard, Adamic-Adar, preferential attachment Score per node pair Used for link prediction. Not used directly in this pack.
Paths & Distances Shortest path, betweenness (edge) Distance or betweenness per node/edge Weights are costs. Shorter path = lower cost.
Projection & Reduction Bipartite projection New graph on one side of bipartite Most consequential choice. Changes the question being answered.
Structural Properties Connected components, diameter, clustering Global graph statistics Used for profiling (P1) and validation.

The Trap: Weight as Cost vs Weight as Strength

Critical: In openflights and crime, edges carry distances or co-occurrence counts. These are costs, not strengths. Higher weight means harder to traverse, not more connected. Shortest-path algorithms minimise cost. Community-detection algorithms with modularity treat weights as connection strength — this is the wrong mental model and leads to wrong conclusions. Always ask: does this algorithm treat weight as cost or as strength?

Why Bother?

Interoperability

RDF triples can be ingested by any SPARQL-enabled triple store. Results from this project can be joined with external biomedical knowledge graphs without schema mapping.

Validation

SHACL shapes enforce that every exported experiment record has the required fields: graph ID, algorithm, parameters, timestamp, provenance URL. Invalid exports are rejected before archiving.

Reasoning

OWL reasoning can infer types and relationships not explicitly stated. For example, if a run uses openflights (a KnowledgeGraph), a reasoner can infer it is also a NamedThing with an identifier.

Archival

Turtle and RDF are W3C standards with decades-long archival stability. CSV and Markdown may be readable in 10 years; Turtle will definitely be readable.
